## 1. 参考工作台是什么

一句话：**不是行情看板，是"结构化交易计划的执行监控台"**——每个品种预先写死一套完整交易剧本（观点、多空两套关键价位、进场触发条件、防假信号确认机制、产业验证条件），行情数据只用来回答一个问题："**剧本走到哪一步了，现在能不能动手**"。

### 1.1 基本架构

| 项 | 实现 |
|---|---|
| 前端 | React + Vite SPA，深色主题 |
| 后端 | tRPC + superjson（`/api/trpc`），类型安全 RPC |
| 行情源 | **天勤（TqSdk）主源 + 东财/新浪备用源**（与我们同源！） |
| 本地存储 | localStorage：交易日志（`fm_journal_v1`）、产业信号标记（`fm_alert_muted`） |
| 品种 | JD 鸡蛋2612 · L 塑料2701 · PP 聚丙烯2701 · M 豆粕2701 · C 玉米2701（具体月份合约，非主连） |

### 1.2 还原出的功能模块

| 模块 | 源文件 | 功能 |
|---|---|---|
| 品种卡片 | InstrumentCard.tsx | 方向建议（做多/做空/观望）、入场价、止损价、**趋势目标+波段目标双层**、第一支撑/强撑/失守目标（各标距现价 %）、合约元数据（乘数/每点价值/夜盘/ATR） |
| 信号矩阵 | SignalMatrix.tsx | 三态信号：🔴触发=满足进场条件 / 🟡接近=距触发位 1% 内 / ⚪观望；**确认状态机**（见 1.3） |
| 产业信号 | IndustrySignals.tsx | 每品种 3 个基本面验证条件（人工确认制），显示"已触发 x/3"，双击确认防误触，本机存储 |
| 资金流 | FundFlow.tsx | 持仓变化**四象限解读**（价涨仓增=多头进场 / 价涨仓减=空头回补…），数据缺失时降级提示"噪声大·仅供参考" |
| 简报中心 | BriefsPanel.tsx | **四个定时简报**：盘前 08:50 · 午检 11:30 · 日结 15:10 · 席位 16:20 自动推送 |
| 今日策略 | StrategyBanner.tsx | 每品种一段策略论文（如"破3400后顺势空、禁止抄底；反弹3500-3520滞涨再试空"） |
| 告警横幅 | AlertBanner.tsx | 🔔/🔕 声音开关 + 告警条 |
| 交易日志 | /journal 页 | 入场/出场记录、可删除，本机存储（换设备手动迁移） |

### 1.3 最有价值的设计：信号确认状态机（防假突破）

每品种预设 4 个关键位：`longTriggerBreak`（多头突破位）/ `longPullback`（多头回踩位）/ `shortBreakdown`（空头破位）/ `shortFadeZone`（空头滞涨区 [起,止]）。

信号不是"碰到价位就报"，而是带**确认流程**：

```
观望 ──现价进入触发位±1%──▶ 🟡接近 ──站上/跌破触发位──▶ 确认中 streak/N根
                                      │
                       连续站稳 N 根 ──▶ 🔴触发（满足进场条件）
                       回落 ──▶ 退回观望/接近
```

配套文案直接写纪律："现价刚站上 3500，持续站稳才确认触发——**别急**"、"刚跌破 3400，持续在下方才确认触发——**别抢跑**"、"未破位、不在滞涨区，等信号"。


## 5. 设计原则（从参考实现提炼，写入项目约定）

1. **行情为剧本服务**：不追求大而全的行情终端，每个数据面板都要回答"对当前剧本意味着什么"
2. **防情绪化内置**：确认机制 + 纪律文案是产品功能，不是装饰（参考实现的"别急/别抢跑/禁止抄底"）
3. **人工确认制**：基本面条件无法自动取数的，用"人工标记 + 双击确认 + 本机存储"，诚实标注数据来源
4. **数据缺失要降级**：备用源缺字段时明说（"天勤恢复供数后自动显示"），不用假数据顶
5. **不构成投资建议**：页面常驻免责标注（参考实现 Home 页有"只记录数据，不构成投资建议"）

## 6. 参考源码落地记录（2026-10-20，用户提供了参考站完整备份）

参考站真实架构：React+Vite 前端 + tRPC/Drizzle + MySQL（quote_cache 表做数据中转）+ 独立 Python 天勤 feeder。拿到源码后逐文件核对，结论与移植如下。

### 6.1 源码结构速查

| 文件 | 作用 | 对我们的价值 |
|---|---|---|
| `app/scripts/push_levels.py` | 日结后用天勤日线重算关键位（MA5/MA20/20日高低/ATR14 + 趋势三分支） | ★★★ 已移植为 `workbench/levels.py` |
| `app/src/lib/signals.ts` | 信号引擎：3 次进 5 次出防抖 + 0.1% 缓冲带 + 滞后信号降级 | ★★ 滞后降级已移植进 index.html |
| `app/api/quotes-router.ts` | 行情三源降级（天勤→新浪→东财）+ 休市不请求 + stale 回吐 | 备用（我们直连天勤，无 HTTP 限制） |
| `app/scripts/tq-feeder.py` | 常驻 feeder：秒级快照 + 分钟K + 按阴阳归属的资金流 + 收盘定格 | 思路与我们 server.py 一致，互相印证 |
| `app/src/components/dash/seasonal-data.ts` | 季节性日历 | **纯人工硬编码文字**，无数据接口。我们的 TqSdk 分合约真算版更硬 |
| `app/contracts/instruments.ts` | 五品种配置（即 playbook 里那批静态关键位的出处） | 已被 levels.py 自动计算取代 |

### 6.2 已落地

1. **关键位自动重算** `workbench/levels.py`：TqSdk 取交易合约日线（20 根）+ 主连日线（1300 根算历史分位），按参考站算法生成 levels/thesis/plan/advice/pctile，写回 playbook.json。收盘后跑一次即可，`--dry-run` 可预览。
2. **对参考站算法的 3 处修正**（我们跑真数据后暴露的）：
   - 现价贴近 20 日低点时，一撑与强撑撞成同一个数 → `fix_ladder()` 保证 压力>一撑>强撑>失守 严格递减，强撑保留"真实前低"语义，一撑抬到其上方 0.35×ATR；
   - 作战卡 entry 与 stop 算出同一个值（两个函数复用同一公式）→ 强制止损距入场 ≥0.5×ATR，且空单止损在上、多单在下；
   - thesis 里的裸 `<` 会被前端 innerHTML 当标签吞字 → 改用全角 ＜＞，前端另加 esc() 转义兜底。
3. **playbook.json 热重载**：server 检测文件 mtime 变化自动重载（保留主力合约映射），改关键位/剧本不用重启。
4. **信号滞后降级**：突破/破位后价格已跑出 0.3×ATR 时，"触发"降级为"已突破·等回踩/已破位·等反抽"，不追高不追空。
5. **凭据文件** `workbench/.tqenv`（chmod 600），levels.py 与 server.py 均自动读取，命令行不用再带密码。

### 6.3 自检与刷新流程

```
python3 workbench/levels.py            # 收盘后跑，写回 playbook.json（自动备份 .bak）
# 页面 3 秒内自动热重载新关键位，无需重启
```

## 8. 多空力量与资金流向：两套实现对比与口径修正（2026-10-20 中午）

### 8.1 参考站的三件套拆解

| 组件 | 实现 | 核心逻辑 |
|---|---|---|
| RealFundFlow（真实资金动向） | `FundFlow.tsx` | 四象限：价格相对昨结算涨跌 × 持仓变化率，≥1% 才算有效信号，其余判"无量整理" |
| FundFlow（资金流向估算） | `FundFlow.tsx` + `tq-feeder.kline_pack` | 当日全部分钟 K 线，逐根「收盘 vs 前一根收盘」定方向，成交额 = 量×收×乘数，归入多/空两侧；无数据时降级为「涨跌幅+换手率」估算模型 |
| SignalMatrix（信号矩阵） | `SignalMatrix.tsx` | 五品种横向：做多/做空信号三态（触发/接近/观望）+ 综合结论"可动手/盯紧/空仓" |

### 8.2 修正前本项目的四个实质差异（两个是硬伤）

| # | 维度 | 参考站 | 本项目（修正前） | 性质 |
|---|---|---|---|---|
| 1 | 时间窗 | 当日累计（自然日过滤） | 固定近 30 根 1m（滚动窗口） | **硬伤**：收盘后窗口停在 14:30-15:00；可能跨夜盘/日盘断裂；金额是 30 分钟窗口的却被当全天看 |
| 2 | 方向判定 | 收盘 vs 前一根收盘 | 收盘 vs 本根开盘 | **硬伤**：单根低开高走但整体仍跌时误记成主动多，下跌趋势系统性高估多头 |
| 3 | 乘数 | 传参 mult（正确） | contractUnit（吨/手） | **bug**：鸡蛋报价元/500kg、1 点值 10 元而单位 5 吨，JD 金额少算一半 |
| 4 | 涨跌基准 | 昨结算 | 昨收 | **矛盾**：显示 +0.81% 上涨、四象限却判空头进攻（昨收与昨结差 86 点） |

### 8.3 量化实测（同一天同一时刻，JD 为例）

| 口径 | 多头占比 | 净额 |
|---|---|---|
| A 近30根 · 收vs开（修正前） | 36.7% | -8.09 亿 |
| B 近30根 · 收vs前收 | 35.4% | -8.72 亿 |
| C 当日累计 · 收vs开 | 42.2% | -15.07 亿 |
| D 当日累计 · 收vs前收（参考站口径） | 44.2% | -10.74 亿 |

结论：口径不是细节，是结论本身。

### 8.4 已落地修正（server.py / index.html）

1. `_flow_amount` 重写：按期货交易日归属（20:00 后计入次一交易日，夜盘 21:00 起算当日）过滤 + 收盘 vs 前收 + 首根跳过；900 根 1m 缓存（K 线不变不重算），PERIODS 推送仍 500 根。

4. 新增字段：flow_bars/flow_start/flow_trunc（覆盖范围与截断提示）、flow_amt/oi_value（当日成交额/持仓市值）、net_ratio（额差÷成交额=失衡度）。
5. 页面措辞去误导：「净流入」→「多空额差」（并注明不是真金白银净流入）；换手分级（成交额/持仓市值 ≥1.2 高频换手·失真大 / ≥0.5 偏高 / 低）。
6. 新增「多空力量」底部标签：五品种横向总表，综合分 = 四象限(±2/±1/0) + 失衡度≥5%(±1) + 信号触发(±1)/接近(±0.5)，排序输出强多→强空，打分口径写在页面底部。

### 8.5 有意保留的差异

- 参考站在无分钟数据时降级为「涨跌幅+换手率」估算模型：不移植。我们直连天勤不会缺数据，降级模型输出的数字看似精确实则编造，宁缺毋滥，缺数据时明确标注"缺失"。
- 参考站 SignalMatrix 的"可动手/盯紧/空仓"结论：不照搬。它的综合结论只看关键位距离，不看资金与持仓；我们的综合分把三者合成且权重透明。且五品种平铺卡片已经承担了单品种深度信息，总表只做横向排序。
- 参考站四象限分母用 `oi - oiChg` 近似昨日持仓：我们用 `pre_open_interest` 优先、缺失才回退，更准。

## 9. 关键位四档（压力/前高·第一支撑·强撑·失守目标）差异与日内位补全

### 9.1 参考站其实是"双轨"，我们原来只有"单轨"

这是"看起来不一样"的最大来源：参考站页面上同名四档出现两次，口径完全不同。

| 轨道 | 数据来源 | 算法 | 更新频率 | 用途 |
|---|---|---|---|---|
| 日内位（蓝色块） | 当日实时行情 | 昨结算 ± ATR：压力=max(今高, 昨结+0.5ATR)、一撑=max(今低, 昨结-0.5ATR)、强撑=昨结-1ATR、失守=昨结-1.5ATR | 盘中每秒 | "今天在哪接"，短线锚 |
| 波段位（黄色块） | 日结任务 push_levels.py | 日线 20 日高低 + MA + ATR 规则化三分支 | 每天收盘后 | "这周在哪做" |

参考站 InstrumentCard.tsx 同时渲染两块，标签一模一样（"压力/前高"），只靠标题行
（📍 日内位 · ATR短线锚 / 📊 波段位 · 每日收盘更新）区分。只看数字不看标题必混。

本项目此前只有波段位一套 → 数值与参考站页面同名的日内位差得远（JD 现价 3339 时，
日内位压力 3359 vs 波段位压力 3851），这就是"指标不一样"的直接原因。

### 9.2 波段位算法本体是一致的，差异有 5 处（全部有意）

levels.py 的 calc_levels/position_advice/judge_bias/ATR 逐行照抄 push_levels.py，
数值差异来自以下修正：

| # | 差异 | 参考站 | 本项目 | 理由 |
|---|---|---|---|---|
| 1 | 当日K线 | `iloc[:-1]` 无条件剔除，15:10 跑实际用"昨日往前20根" | `drop_unfinished`：盘中剔除、收盘后保留当日 | 收盘后当天K线已完整，扔掉白扔一天数据 |
| 2 | 撞值 | 无自检：现价贴近20日低时 一撑=强撑=low20（JD/M/C 都出现过） | `fix_ladder` 保证四档严格递减，一撑抬到强撑上方 0.35ATR | 两档同数没有信息量 |
| 3 | range 失守目标 | 算法本身正确，但静态快照里 L/PP 出现"失守目标 > 强撑"倒挂 | 写盘前自检四档递减，倒挂直接拒绝落盘 | 静态值是手写的，算法没错 |
| 4 | 合约 | 写死 JD2612 等，换月要改代码 | `query_cont_quotes` 动态解析主力 | 防换月后算错品种 |
| 5 | thesis 符号 | 裸 `<` `>`，前端 innerHTML 渲染会吞字 | 全角 ＜＞ | 渲染安全 |

JD 实测对照（2026-10-20，昨结 3372，ATR 87）：
- 参考站原算法：压力 3851 / 一撑 **3235** / 强撑 **3235** / 失守 3191（一撑强撑撞值）
- 本项目 fix_ladder 后：压力 3851 / 一撑 **3266** / 强撑 3235 / 失守 3191
- 参考站静态快照（手写）：压力 3500 / 一撑 3300 / 强撑 3266 / 失守 3250（与算法无关）

### 9.3 已落地：日内位补全（server.py + index.html）

1. `_quote_row` 新增 high/low/open 三个当日字段（日内位原料）。
2. 前端 `renderLadder` 重构为双轨渲染：
   - 波段位维持原四档大卡片，上方加标题「波段位 · 日线20日 + 截至 xx 收盘」；

## 12. 「资金流向估算（分钟级）」与「多空力量」实现对照

### 12.1 结论

两块都已实现且在跑（2026-10-20 14:14 实测五品种全部有数据）。对应关系如下。

### 12.2 资金流向估算（分钟级）

参考站实现位置：`scripts/tq-feeder.py` 的 `kline_pack`（服务端算）+ `FundFlow.tsx`（展示）。

| 维度 | 参考站 | 本项目 | 评价 |
|---|---|---|---|
| 数据粒度 | 1 分钟 K 线（tail 300 根） | 1 分钟 K 线（TqSdk 常驻订阅） | 相同，都是 K 线级近似，不是逐笔主动买卖 |
| 时间窗 | 按自然日过滤 `_date==today`，注释自承"为简化"（夜盘 21:00-23:00 算当天） | 交易日归属：20:00 后计入次一交易日，夜盘整体归 T+1 | 本项目更严：跨周末夜盘不会把周五夜盘成交算进周一 |
| 方向判定 | 当前分钟收盘 vs 前一根收盘，`c >= prev` 记多 | 相同；另补了窗口边界——交易日首根用上一交易日末根收盘做基准（隔夜跳空计入） | 本项目少漏一根 |
| 金额乘数 | `v*c*mult`，mult 由调用方传 | `v*c*pointValue`；JD 报价元/500kg，用 contractUnit 会把金额少算一半 | 本项目修正了参考站的乘数隐患 |
| 缺数据回退 | 有：涨跌幅+换手率的公式**编造** longPct/netFlow | 无：缺数据就明示"资金流数据缺失" | 有意不移植，编造数字比缺数据更危险 |
| 展示 | 多空对比条 + 净流入亿 + 持仓/市值/换手率 | 四象限徽章 + 持仓变化 + 多空额差（亿）+ 失衡度% + 对比条 + 口径/噪声分级 | 本项目信息更多 |
| 实测 | — | JD -18.39亿/失衡-13.3%、L +37.16亿、PP +16.56亿、M +38.56亿、C +45.68亿，开盘起累计 183~303 根 | ✓ |

参考站的"换手率"（vol/oi）在本项目里用「成交额/持仓市值」等价呈现（`flow_amt/oi_value`），
还是噪声分级的输入——金额口径不受报价单位影响，比手数口径跨品种更可比。

### 12.3 多空力量

参考站**没有**叫"多空力量"的模块，语义上对应两处：

1. `FundFlow.tsx` 的「多空对比条」（多 X% / 空 Y%）→ 本项目卡片 `renderFlow` 已有，同款红绿条。
2. `SignalMatrix.tsx`「信号矩阵·三级触发」五品种汇总 → 本项目升级成独立**「多空力量」标签页**：
   - 每行：现价/涨跌、持仓×价格四象限、持仓变化、多空额差、失衡度、多空额比、剧本信号、综合倾向
   - 综合分（透明口径）：四象限 强多+2/弱多+1/观望 0/弱空-1/强空-2；失衡度≥±5% 按方向 ±1；信号触发 ±1/接近 ±0.5
   - 实测排序：塑料 强多+3 > 玉米 偏多+2.5 > PP 偏多+2 > 豆粕 中性+0.5 > 鸡蛋 强空-4

**有意不移植**：SignalMatrix 的「可动手/盯紧/空仓」三态结论。它只看"信号是否触发"，
既不含资金也不含方向强度，本项目把它拆成「信号」列（触发/接近）和「综合倾向」列
（四象限+资金合成），信息量更大；两列并列的"做多信号/做空信号"在两侧同时亮时无法分辨，
也没有保留价值。

### 12.4 尚存的口径差异（有意保留）

- 参考站四象限显著阈值 = 持仓变化 ≥1%；本项目同阈值（flat=无量整理）。
- 本项目多空额差含夜盘（交易日归属），参考站按自然日截断——上午看参考站"今日"只有
  日盘数据，本项目含昨晚夜盘，绝对值不可直接互比，方向一致性才是对齐目标。

## 14. 「真实资金动向」补多空占比（持仓动作归属）

### 14.1 口径设计

资金流向块的多空占比用**成交额**归属（钱往哪砸）；真实资金动向块补的这条用**持仓变化**归属
（仓往哪挪）——同一批分钟 K 线的 close_oi 逐根变化 ΔOI，按「价格方向 × 增/减仓」归到动作方
（四象限命名与 TqSdk ta 模块一致）：

| 价格 | ΔOI | 语义 | 归属 |
|---|---|---|---|
| 涨 | 增仓 | 多头增仓 | 多方 |
| 跌 | 减仓 | 多头离场 | 多方 |
| 跌 | 增仓 | 空头增仓 | 空方 |
| 涨 | 减仓 | 空头回补 | 空方 |

两个口径不能互相替代：**减仓日会明显背离**——成交额可能很大（平仓也成交），但持仓动作小；
只看资金流会把「平仓离场」误读成「新资金进场」。鸡蛋（持仓 -4976 手的减仓日）就是典型。

### 14.2 实现

- `server.py _flow_amount`：新增 oi_long / oi_short / oi_net / oi_bars（手数，按上表归集），
  `_quote_row` 输出 `oi_ratio`（多方占比 %）；沿用同一套交易日归属与首根基准边界。
- `index.html`：真实资金动向块在四象限双格下加「持仓动作」bar（左侧标签区分下方资金条），
  悬停给出口径说明 + 今日多/空手数与参与根数；数据缺失显示灰条「数据缺失」。
- 复用 `.flowbar` 样式，新增 `.barrow/.barlbl/.na` 三条 CSS。

## 15. 「真实资金动向·多空力量」对齐参考站（2026-10-20 16:05）

### 15.1 问题

上一轮给「真实资金动向」补的多空占比走的是自创口径：逐分钟 ΔOI 按涨跌归属到动作方，
统计出"多 42% / 空 58%"这类**连续趋近 50% 的实测值**。参考站显示的是另一套完全不同的数字，
两边放一起对照时差距很大，用户无法用参考站校对本页。

### 15.2 参考站算法（反编译 FundFlow.tsx 确认）

```
四象限基准占比 D：多头进攻 100 / 空头进攻 0 / 空头回补 35 / 多头离场 65 / 无量整理 50
强度 X = min(|ΔOI%| / 3, 1)
多头占比 = round(50 + (D − 50) × (0.5 + 0.5 × X))
新增头寸(亿) = ΔOI × 现价 × 乘数 ÷ 1e8
多/空金额 = |新增头寸| × 多头占比 / 空头占比
「多头/空头净流入」= max(多金额, 空金额)
```

要点：**占比不是统计值，是四象限定性结论的量化**——变化率 ≥3% 时完全取基准值，
越小越向 50% 收敛。所以参考站常见 95%/96% 这种极端值，而实测口径永远在 50% 附近抖动，
这就是"差距比较大"的全部来源。

### 15.3 本项目落地（2026-10-20 16:05 起）

- `server.py` `_quote_row`：新增 `oi_ratio_ref`（参考站口径占比）与 `oi_amt`（新增头寸，亿）。
- `index.html` `renderFlow`：真实资金动向块的「持仓动作」条替换为参考站同款「多空力量」条 +
  「多头/空头净流入 X 亿 · 多 A / 空 B 亿 · 新增头寸 ±C 亿」一行；悬停写明完整算式与当前参数代入值。
- 原"分钟实测手数占比"**保留**为下方小字一行（标注"另一口径"），减仓日与参考口径会背离，
  两套并存互相印证（玉米 2026-10-20：参考口径 96% 偏多 vs 实测 53%，资金流 73% 偏多）。
- 乘数差异：本页统一用「元/点」，参考站此块用「合约单位」。四个品种两者相同，仅鸡蛋不同
  （合约 5 吨 vs 1 点 10 元），鸡蛋的新增头寸/金额本页是参考站显示值的 2 倍——悬停里有说明。
