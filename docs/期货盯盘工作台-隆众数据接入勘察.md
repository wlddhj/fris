**这些数据隆众确实有，而且更新很勤（聚烯烃库存每天 9–10 点发，开工率/产能利用率每周四发），但正文全部在登录墙后面。**

## 3. 抓取可行性实测

### 3.1 反爬：只是 brotli 压缩，没有验证码

- 首页、品种页、列表页 `curl` 直接 200，但响应是 `Content-Encoding: br`，本机 curl 没编 brotli 所以是乱码；Node `zlib.brotliDecompressSync` 解压即得完整 HTML（26 万字符）。
- 无需 cookie、无需 UA 伪装之外的手段，**限速不敏感**（连续 6 个请求无异常）。

### 3.2 登录墙：正文被服务端替换（决定性）

```html
<div class="xq-content" id="content">
  <table class="chrg">
    <tr><td class="line1"><font>免费开通</font></td><td class="line1"><font>会员登录</font></td></tr>
    ...
```

带「先访问首页拿 cookie」的会话复测：首页不发任何 Set-Cookie，正文仍是登录表单 —— 说明是**按登录态渲染**，不是缺 cookie 的问题。

### 3.3 数据终端 dt.oilchem.net：能进，但品种数据要登录态

品种页上「产能/产量/开工率/利润/进出口/库存」的入口是 `https://dt.oilchem.net/home?token=e04924a6a985d282626fc25d67a59485`（分享 token）。

实测：
- token 可直接进站，首页、排行榜页面框架都正常渲染（无需账号）
- 但品种维度接口全部收到 `breedId=undefined`，页面显示「暂无数据」：
  - `POST /api/widget/queryData/operatingRate`
  - `POST /api/breed/supply/operateDateCompareByYear`
  - `POST /api/breed/getFrequencyListByParam {"quotaType":"开工率"}`
  - 试过 `?breedId=314`（PE）、`/breed/supply/operatingRate?breedId=314` 均无效，SPA 从登录态/内部 store 取品种，不从 URL 取
- 匿名能通的只有导航字典：`GET /api/channel/navigation/queryByName?name=聚乙烯` → `PE#314`、`PP#317`（可用来做品种 ID 映射）

结论：**终端这条路的最后一步（抽数值）仍卡在登录态**。

## 4. 三条可选路线

| 路线 | 做法 | 数据质量 | 工作量 | 风险 |
|---|---|---|---|---|
| **A. 隆众账号登录** | 你在浏览器登录隆众（免费注册即可），把 Cookie 贴给我 / 我读一次浏览器 Cookie；后端 `longzhong.py` 带 Cookie 抓那 4 个栏目最新一期正文，正则抽数值 | 最好：一手数据、口径与行业标准一致、日/周更齐全 | 中（约 300 行 + 4 条 autosig 规则 + 卡片渲染） | Cookie 有有效期（约 1–4 周），过期需要重贴；正文是表格 HTML，要按品种解析 |
| **B. 免登录替代源** | 抓期货公司日报/财经媒体的转引数字（如「聚烯烃两油库存 78.5 万吨(-1)」「PE开工率 71.36%，PP开工率 63.53%」「塑编 39.7%、注塑 39.25%、BOPP 30.15%」） | 次之：数值基本同源（多是转引隆众/卓创），但**更新时点滞后**、字段名各家不统一，需要逐源写正则 | 中偏高（每源一套解析，源站改版就断） | 源站结构变化、纯文本较脆；同花顺移动页正文是 JS 加载，要无头浏览器 |
| **C. 混合** | A 为主，抓不到（Cookie 过期/栏目无更新）时自动回退 B，页面上标「隆众原文 / 转引」 | 兼顾 | 高 | 维护两套 |

## 5. 建议

先走 **A**。理由：

1. 这 4 项里两油库存是**日更**，最需要自动化；隆众原文同时给出「本日值 / 较昨日 / 较去年同期」，做「连续 2 周环比下降」这类判定时不必自己攒历史。
2. 栏目列表页可直接拿到最新一期 URL（标题里带日期和周期），不用处理翻页/搜索。
3. 免费注册账号即可，成本最低，且后续还能扩到 PE 下游开工率、PP 港口库存等没进 playbook 的指标。

需要你提供的：**一个隆众账号的登录 Cookie**（浏览器 F12 → Network → 任意请求 → 复制 Request Headers 里的 Cookie 整行）。我会把它存在 `workbench/config.json` 的 `longzhong.cookie`，只本机使用，不进代码库。

拿到 Cookie 后我能交付：
- `longzhong.py`：4 个栏目轮询（库存日更 30 分钟一次、周更栏目 4 小时一次），落 `longzhong.json`
- `autosig.py`：`l1_pe_oprate`、`l2_twooil_stock`、`pp1_pp_stock`、`pp2_pp_downrate` 四条自动规则
- 卡片：L / PP 卡新增「隆众数据」块（数值 + 环比 + 数据日期 + 来源），与玉米卡的中储粮块同款样式

自动信号判定结果（首次真实判定）：

### 实现要点

- **当天即可判「连续两期」**：抓当期文章时顺手取上一期原文（每篇原文都写「较上期 ±X」），
  不必等本地 history 攒 3 期（周更那要等 3 周）。history 仍照常累积，作第②条判定路径。
- **请求节流**：栏目里最新一期 URL 与上轮相同就直接复用上轮解析结果，每轮请求约 4 次；
  429/5xx 指数退避重试 3 次（实测连抓 5 篇就会触发 429）。
- **系列锁定**：PP 库存栏目混着生产企业/贸易商/港口三个系列，标题正则收紧为
  `聚丙烯生产企业库存`，避免把「港口 0.95 万吨」当成生产企业库存的上一期（实际踩过）。
- **涨跌方向**：隆众把方向词写在数字前好几个字（「与上期库存下降 1 万吨」），
  改为取数字位置往前扫 16 字判断符号，不再依赖方向词贴着数字。
- **前端**：L / PP 卡片新增「隆众 · 产业数据」块（蓝灰色条，与中储粮金色条区分），
  显示数值 + 环比 + 数据日期；JD/M/C 卡不显示。无权限 / Cookie 过期 / 未配置各有明确文案。
- **口径修正**：playbook 里 l2/pp1 原写「连续 2 周环比下降」，实际数据源是日更的两油库存
  与周更的 PP 生产企业库存，判定为「连续两期（期 = 文章期数）环比下降」，文案已同步。
  注意日更口径下「连续两日下降」比原意（两周）宽松，后续若嫌信号太松，可改成
  「近 5 期累计降幅」——history 攒几天后就具备条件。
